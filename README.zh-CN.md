# AI 电商带货视频 Skill

[English](README.md)

`ai-commerce-video` 是一个面向 Codex 的开源 Skill。普通用户只需要提供商品图片和简短需求，Codex 就可以通过多模态能力分析商品、平台、受众和卖点，设计带货广告方案并准备实际生成用图；用户最终确认后，再执行付费视频生成、拼接、字幕和质量验收。

## 核心特点

- 默认生成适合电商转化的 15 秒商品广告。
- 支持抖音、TikTok、小红书、Amazon、Meta、YouTube 和独立站等场景规划。
- 采用两次有意义的确认：阶段 1 确认专业广告方案、分镜、转场、图片提示词和视频提示词蓝图；阶段 2 确认实际参考图并授权付费生成。
- 用户上传的商品图、细节图、人物图和场景图全部只作为分析证据，零张直接进入默认 R2V。阶段 1 通过后，重新生成完整 Reference Pack：第一张是忠实于同一 SKU 的专业商品主控图，后续才是必要的人物、服装、空场景、手部动作、细节、道具、风格或关键帧控制图。禁止裁切、复制、改名或仅去背后复用用户图。
- 用户提供同一 SKU 的多张可信图片时，Codex 会把它们作为生图参考，优先生成商品主控图和完整分镜关键帧。项目可以保存生图证据记录，但缺少逐图 ID、路径、哈希或 AI 质检结论只会提示，不会增加门禁；阶段 2 由用户直接确认实际大图。
- 分镜拼图只用于用户审核，不上传 Reference-to-Video；需要构图引导时可把每个重要节拍生成成独立的干净全屏关键帧，与其他参考图一起用于同一次 R2V。需要精确控制切镜首帧时，才改用分段图生视频并重新确认实际付费次数。
- 阶段 2 会展示严格按 API 顺序排列的 `<IMAGE_0>`…参考图、最终提示词含义、字幕选择和付费次数；回复 `确认并生成` 后直接进入受保护的 API 流程。
- 视频模型禁止直接生成字幕、价格、CTA、角标、水印等文字。
- 字幕默认关闭；用户需要时，先生成干净视频，再按成片实际语音通过本地后期生成和烧录。
- 每个计划镜头只允许提交一次付费请求；接口状态不确定时继续查询原任务，不自动重复付费。
- Grok 视频提示词采用 `director-commerce-v8`、`universal-product-director-v4` 和计划结构 v3：所有行业先生成同一份“商品形态、交互方式、证明方式、人物价值、事实边界”导演画像，品类名称不再选择独立模板。每个语义节拍写清商业任务、入场状态、完整主体动作、构图、一个主运镜及速度、焦点、灯光/物理响应、稳定离场状态、转场和与画面动作同步的完整声音。编译器只输出一个 `Cuts` 商业剪辑时间轴或一个 `Sequence` 连续镜头时间轴，以及一次参考图映射和一次 `AUDIO`。
- 只要方案有口播，默认直接在唯一 `AUDIO` 区块里写清台词/旁白，以及语言、语气、节奏、情绪或声音风格；普通流程不再冻结 `voice_id`、不发送 `reference_audios`，也不依赖 `/v1/tts/voices`。只有用户明确指定 Provider 预设声线时才启用可选声线引用。声线描述不等于逐帧精确口型；有 AAC 音轨也不代表有清楚人声，最终仍要检查口播是否可理解、带货含义是否保留。
- 人声和音效仍会专业设计，但声音覆盖缺项和逐层试听改为提示或可选复审，不再阻断普通视频生成。每个独立片段会尽量写全标志音、环境声、音乐和混音；原生声音属于模型尽力遵守。必须保留的技术交付条件仍包括视频可解码、时长合理、拼接正确和 `delivery-manifest.json.status=pass`。
- 默认 Reference Pack 优先使用“商品主控图 + Hook 全屏关键帧 + Proof/Payoff 全屏关键帧”；人物、场景和动作图只有确实解决控制问题时才增加。没有商品证据时禁止发明滴管、泵头、喷嘴、按钮、接口或开合结构。
- 付费次数按具体路由已验证的稳定时长规划。官方 xAI R2V 文档支持单次 15 秒；当前 MikuAPI R2V 两个实际 15 秒请求都只返回约 10.042 秒，因此可靠规划上限改为 10 秒，15 秒成片默认显示为 `10+5`、2 次付费请求。每个完整语义动作只分配给一个请求，跨段边界保存稳定出段状态、连续入段状态、切镜动机和声音桥，禁止把同一动作拆成两半交给两个随机生成请求。
- 提示词长度的 4096/3000 等数值明确标为适配器和工作流内部预算，不冒充 xAI 官方公开上限。编译器会显示创意执行、参考图映射、底线和声音占比，防止长篇固定说明挤占镜头导演空间。
- Provider 实际片段比批准时长短超过 1 秒时直接阻断交付，不能靠长时间静止末帧补成“完整 15 秒”；末帧正常保持最多约 1 秒。
- 请求保存提示词、载荷和实际图片指纹；结果保存网关任务、上游任务、通道和图片接收凭证状态。
- 默认通过 MikuAPI 中转调用 `grok-imagine-video-1.5` Reference-to-Video：请求合同支持 1–7 张参考图、1–15 秒、最高 720p，但当前稳定规划单段不超过 10 秒。通常只选 3–5 张职责明确、不冲突的参考图。
- 自动生成“确认首图 vs 视频首帧”对比图，技术解码成功不等于业务画面正确。
- 长视频按“拼接完整合理、参考人物/服装/场景/构图基本一致、语音清楚且卖点大意一致”验收，不要求逐字复现脚本。

## 当前适配的视频模型

| 配置名称 | 接口适配层 | 实际模型 ID | 已适配能力 |
|---|---|---|---|
| `grok_video_15_reference` | MikuAPI 中转 | `grok-imagine-video-1.5` | 默认路线；1–7 张参考图、原生音频、请求可填 1–15 秒、当前可靠规划上限 10 秒、最高 720p |
| `grok_video_15_reference_xai` | xAI 官方 | `grok-imagine-video-1.5` | 可选直连路线；视觉能力和多参考图合同与默认路线相同 |
| `grok_video_15` | MikuAPI | `grok-imagine-video-1.5` | 保留的单张首帧兼容路线 |
| `grok_image_video` | 第三方 `119337` | `grok-image-video` | 文生视频或参考图视频；最多 7 张参考图；单图最长 15 秒，多参考图最长 10 秒 |
| `seedance2` | fal queue | `bytedance/seedance-2.0/reference-to-video` | 最多 9 张参考图、原生音频、最长 15 秒 |

重要说明：

- 默认 MikuAPI 路线只读取 `AI_COMMERCE_VIDEO_MIKUAPI_KEY`；macOS 推荐保存在钥匙串服务 `ai-commerce-video-mikuapi-video`。
- REST 字段是 `reference_images`；`reference_image_urls` 是 Python SDK 参数。它与单图首帧字段 `image` 互斥。
- 官方 xAI 可选路线使用独立的 `XAI_API_KEY`，不会自动代替默认 MikuAPI 路线。
- `grok_image_video` 是保留的可选旧适配器，不会成为默认路由；它仍属于第三方 119337 协议。
- 119337 路由只读取独立变量 `AI_COMMERCE_VIDEO_119337_KEY` 或钥匙串 `ai-commerce-video-119337-video`，不会复用其他 Provider 的密钥。
- 模型名称相同不代表接口兼容。真正的适配对象是“接口地址、鉴权方式、请求字段、模型能力、时长、参考图限制、返回格式和轮询流程”的完整组合。

## 切换其他视频模型

如果需要切换 Kling、Veo、Runway、其他 Grok 网关或新版本 Seedance，必须根据新模型能力优化这个 Skill，不能只修改模型名称。

至少需要检查和适配：

1. 新建独立的模型配置，不覆盖已经验证的模型配置。
2. 配置创建任务、查询任务和获取结果的接口地址。
3. 配置专用 API Key 环境变量，禁止不同服务商混用密钥。
4. 配置文生视频、单图、多参考图、首尾帧、视频延长等输入能力。
5. 配置模型允许的时长、分辨率、画幅和参考图数量。
6. 分开确认原生语音、中文口播、声线条件控制和精确口型能力，不能把“有音轨”或“支持声线”写成逐帧口型保证。
7. 配置真实请求字段以及任务成功、失败、超时的返回格式。
8. 根据模型能力调整分段策略、参考图策略、提示词长度和连续性要求。
9. 增加离线请求测试、模拟提交/轮询测试、免费预检测试和密钥隔离测试。
10. 重新运行全部测试和开源发布审查。

## 项目级使用

保留当前项目中的这一份 Skill，在 Codex 请求里直接附上或引用项目内 `SKILL.md` 的路径，不需要再复制一份到全局目录：

```text
请使用当前项目 SKILL.md 中的 ai-commerce-video Skill。
```

用户可以直接提供：

- 一张或多张商品图；
- 希望发布的平台；
- 视频时长；
- 带货风格；
- 是否需要真人/数字人口播；
- 是否需要后期字幕。

信息不完整时，Codex 会以广告策划和电商视频导演的身份补充合理假设，并给出推荐方案。

## 标准制作流程

1. 分析商品图片、卖点、受众和平台。
2. AI 自动选择推荐方案，并保留一个简短备选方向供用户需要时修改。
3. 阶段 1 展示专业视觉方案：15 秒分镜/脚本、切镜依据、参考图组合、每张图片提示词和最终视频提示词蓝图。
4. 用户确认方案后，Codex 根据商品证据生成全部实际视频控制图或全屏分镜关键帧，并运行一次统一免费预检。
5. 阶段 2 展示按 API 顺序排列的实际参考图、最终提示词含义、字幕选择和准确付费次数。
6. 用户回复 `确认并生成` 后直接进入确认和提交；不会再拆开询问口播、预检和付费。
7. 首次提交前自动做一次免费服务检查；若遇到地区限制、网络问题或模型不可见，不会创建视频任务，也不会消耗付费次数。网络恢复后沿用原确认直接继续，无需重复确认。
8. 视频任务按已显示的次数提交，每个镜头只提交一次，并通过任务 ID 查询或恢复。
9. 多段视频只在完整动作、稳定画面和完整语句边界拼接；中间使用 PCM，最终只编码一次 AAC。
10. 完成必要的技术验收：视频可解码、时长和拼接正确、文件与任务记录一致。商品、人物、语音和声音设计的详细业务复审按需执行，不再成为默认第三道门禁。
11. 如用户确认需要字幕，再进行本地字幕制作。
12. 只有 `delivery-manifest.json` 为 `status=pass` 才能称为正式交付。

## 私密配置

执行：

```bash
python3 scripts/setup_private_env.py
```

如果该服务商必须经过你现有的本地代理，可以只给本 Skill 指定地址：

```bash
python3 scripts/setup_private_env.py --proxy-url http://127.0.0.1:7897
```

这只会写入 Skill 的私密环境文件，不会修改 Clash 的节点、规则、端口或系统代理设置。

密钥会保存在：

```text
~/.codex/ai-commerce-video.env
```

真实 API Key 不得写入仓库、项目计划、请求日志、测试文件或 `.skill` 安装包。
配置检查只显示密钥是否存在，不再显示任何密钥片段。

## 当前限制

- 默认推荐 15 秒视频。
- 家居、美妆、食品、服装、汽车、家电、软件、宠物用品和未知商品都共用一套证据驱动的导演与提示词架构，只通过结构化商品形态、交互和证明方式适配创意，不使用品类关键词模板分叉。
- 只要超过当前路线的可靠单段上限就会分段生成并拼接；分段文件能够拼接不代表人物、声音、口型和动作一定无缝连续，因此必须做边界与声音连续性验收。
- 第三方模型网关的能力和价格可能变化，付费生成前必须重新预检。
- 第三方网关可能不返回图片接收指纹。此时系统只能证明图片已正确发出，不能证明上游正确绑定；若成片完全跑题，应保留任务链证据向服务商核查，不能自动付费重试。
- 如果服务商在系统已发出一张图片的情况下仍返回“必须正好一张参考图”，请求会记录为 `provider_image_contract_mismatch` 并停止，不会轮流尝试备用字段造成重复扣费。
- 平台规则属于制作规划参考，正式投放前需要复核平台最新政策。
- 合规说明不能代替法律意见。
