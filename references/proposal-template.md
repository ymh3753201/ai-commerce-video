# 专业多参考图带货视频两阶段确认模板

普通用户只需要做两次有意义的决定：先定专业广告方案，再确认实际参考图并授权一次付费视频生成。不要把任一阶段拆成许多小确认。

## 阶段 1：商业视觉方案确认

```markdown
## AI 带货视频视觉方案

### 1. 商品与广告目标

- 商品与现有素材：
- 通用导演画像：商品形态 / 交互方式 / 证明方式 / 人才价值 / 事实边界：
- 核心卖点/证据：
- 目标用户与平台：
- 我补充的合理假设：
- 不得虚构或改变的事实：
- 包装/Logo/现有文字完整性：
- 图片质量风险与商品锚点处理：

### 2. AI 推荐的广告方向

- 唯一商业主张：
- 受众欲望/阻力：
- 可视化证据：
- 广告大创意：
- 情绪曲线：
- 人才作用：增强欲望/信任/尺度/使用证明/情绪中的哪一项：
- 声音策略：`layered_native` / 明确无配乐的 `ambience_led` / 明确纯口播的 `voice_only`
- 声音大创意、场景声床与能量曲线：
- 提示词人声描述：
- 一句话创意：
- 为什么适合这个商品：
- 可选方向（仅供一个有价值的修改方向，不强迫多选）：
- 视觉系统：场景、色彩、光线、镜头、节奏、声音：
- 出镜/讲解方式：
- 人才/特效导演判断：
- 唯一主风格：cinematic_product_hero / use_demo / lifestyle / unboxing_macro / ugc_spoken / before_after
- 商品运动规则：普通商品不自行说话、走动、呼吸或变形。

| 节拍与时间（导演填写） | 商业任务 | 入场状态 → 完整主体动作 → 离场状态 | 构图 / 一个主运镜、速度与焦点 | 灯光/物理响应、转场与同步声音 |
|---|---|---|---|---|
| 节拍 1：____–____ 秒 | Hook 与商品识别 |  |  |  |
| 节拍 2：____–____ 秒 | Proof/Payoff |  |  |  |
| 节拍 3–4（仅按创意需要增加） | 独立利益兑现或 Packshot |  |  |  |

> 转场应由手势、商品形状、遮挡、甩镜、对焦、动作延续或声音推动，不使用无意义的随机特效。生成模型不能保证逐帧精确剪辑。

### 3. 计划使用的参考图（最多 7 张，通常 3–5 张）

| 计划标签 | 角色 | 事实资产 ID/已观察机制 | 锁定内容 | 图片生成提示词 |
|---|---|---|---|---|
| `<IMAGE_0>` | product | 具体 `input_evidence_*` / 只列证据可见结构 | 忠实锁定同一 SKU 的外形、比例、颜色、材质、包装布局、Logo 位置与现有标记，同时升级清晰度、布光、背景和构图 | 单商品专业主控图；不得裁切、复制或仅去背复用原图，不新增/删改商品细节 |
| `<IMAGE_1>` | beat_keyframe_hook | 具体证据 ID / 已观察机制 | 单张全屏 Hook 广告构图 |  |
| `<IMAGE_2>` | beat_keyframe_proof_payoff | 具体证据 ID / 已观察机制 | 单张全屏 Proof/Payoff 广告构图 |  |

- 不会为了凑满 7 张而增加重复或冲突图片。
- 每张图只承担一个主要控制任务。
- 每张图保存角色和生成提示词；事实来源、机制记录和 AI 一致性意见按可获得信息记录为提示，不增加确认步骤。没有证据时禁止新增滴管、泵头、喷嘴、按钮、接口或开合结构。
- 用户上传的所有图片都只作为事实证据，零张直接进入视频模型。
- Image 2 生成完整 Reference Pack，包括第一槽专业商品主控图和后续单主体控制图。
- 阶段 2 直接展示商品主控图实际大图；用户认为不合格时才重新生成，禁止回退到原图。
- 分镜拼图/故事板只供人审核，不作为 Reference-to-Video 元素参考图。
- 如必须精确控制每个切镜首帧，将改用分段图生视频，并在阶段 2 明确展示新的付费次数。

### 4. 逐镜头生成与声音蓝图

| 单次请求内节拍与时间 | 商业任务 | 完整动作与稳定出口 | 一个主运镜/速度/焦点 | 逐字台词 | 同步音效/环境声/配乐线索 |
|---|---|---|---|---|---|
| 节拍 1：____–____s | Hook |  |  |  |  |
| 节拍 2：____–____s | Proof/Payoff |  |  |  |  |
| 节拍 3–4（按需） | 独立 Payoff 或 Packshot |  |  |  |  |

- 中文口播总量：目标约 38–48 个可见汉字，并通过总时长检查。
- 混音方向：口播清楚在前；标志音效对齐可见动作；环境声连续；原创器乐在人声下压低。
- 单条 Grok 提示词：唯一 `Cuts` 或 `Sequence` 时间轴 → 精简视觉方向 → 精简参考图映射 → 商品与事实保护 → 唯一 `AUDIO` 块。
- 多次请求：每个完整语义节拍只属于一个请求；逐边界列出稳定出段状态、连续入段状态、切镜动机和声音桥；每个独立片段重新写全相同的乐器/节奏/质地、环境、标志音和混音，不使用“沿用上一段”。
- 原生声音边界：模型按提示词尽力生成声音层；若要求多段使用完全相同的配乐，需单独批准本地后期音乐/混音，不能仅靠提示词承诺。
- 禁止内容：分镜格、箭头、字幕、价格文字、CTA 文字、水印、虚构包装、商品自行运动、同一节拍多主运镜。
- 预计付费次数：按所选路由的已验证可靠时长上限计算。当前 MikuAPI R2V 的 15 秒成片为 `10+5`、2 次；官方 xAI R2V 才是单次 15 秒。

### 5. 下一步

这一步只确认广告方案，不调用视频 API。回复 `方案确认，生成参考图` 后，我会依据方案生成全部视频参考图，另行生成需要的审核分镜图，检查商品一致性，再进入最终确认。
```

## 阶段 2：实际参考图与付费生成确认

```markdown
## 实际参考图与最终生成确认

### 1. 实际生成用图（严格按 API 上传顺序）

| 标签 | 实际图片 | 本地路径 | 作用 | 检查结果 |
|---|---|---|---|---|
| `<IMAGE_0>` | [展示图片] |  | 商品身份 | 通过/需修改 |
| `<IMAGE_1>` | [展示图片] |  |  | 通过/需修改 |

- 最终提交给视频模型的图片数量：
- 这些图片是参考约束，不会强制成为视频第一帧。
- `<IMAGE_0>` 是基于用户商品证据重新生成的专业商品主控图；用户原图不会上传。AI 一致性意见如有异常会作为提示展示，不替代用户对实际大图的确认。
- 审核用分镜图：已展示/不需要；不会上传 Reference-to-Video。
- REST 请求只使用 `reference_images`，不会与单图首帧字段 `image` 混发。

### 2. 最终广告方案

- 按所选路由列出每次请求的完整节拍、转场与拼接顺序（当前 MikuAPI R2V 的 15 秒也是 `10+5`）：
- 大意口播：
- 提示词人声描述：
- 请求中的声音方式：默认由台词/旁白 + 语言、语气、节奏、情绪或声音风格描述直接生成人声；只有用户明确选择预设声线时才显示 `reference_audios` + `<AUDIO_0>`
- 请求中的声音设计：列出声音大创意、逐节拍同步音效、环境声、原创器乐能量关系和混音；若明确不配乐，仍需说明 SFX 与环境声如何承担声音场景。
- 最终视频提示词含义：
- 平台/比例/清晰度：
- 字幕：默认关闭；如启用，先生成干净视频，再按成片实际语音本地制作。

### 3. 付费与安全

- 预计付费生成次数：根据实际路由写出每段时长；MikuAPI R2V 当前 15 秒为 `10+5`、2 次，官方 xAI R2V 可为 15 秒、1 次。精确首帧 I2V 只有用户明确选择时才提高次数。
- 每个计划镜头只提交一次；不会自动重试、换字段或增加付费次数。
- 免费预检结果：通过/未通过。
- 声音提示：默认提示词原生人声不访问声线列表接口；口播、人声描述、SFX、环境声、配乐和混音缺项作为优化提示，不另设付费门禁。预设 `voice_id` 仅在用户明确要求时作为可选增强。

### 4. 最终授权

确认这些实际图片和方案后，回复 `确认并生成`。这将授权把上面的同一组图片和冻结提示词提交给视频 API。任何实际图片、创意含义、声线、字幕选择或付费次数发生变化，都必须重新进行本阶段确认。
```

## 内部记录要求

`generation-plan.json` 必须保存 `visual_design_contract`、全部图片提示词、实际 `<IMAGE_n>` 映射、平台/场景/合规合同、完整 Provider 提示词、请求载荷摘要、素材哈希、字幕选择和付费上限。最终交付仍以 `delivery-manifest.json.status=pass` 为准。
